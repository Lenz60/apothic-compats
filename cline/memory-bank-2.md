# MEMORY BANK — Part 2 of 3 (API Port Map + Data Conversion)

## 4. API PORT MAP (NeoForge 21 -> Forge 47)
- Packages: `net.neoforged.*` -> `net.minecraftforge.*`; Apotheosis 8.x `dev.shadowsoffire.apotheosis.affix/loot` -> 7.x `dev.shadowsoffire.apotheosis.adventure.affix/loot`; apothic_attributes->attributeslib; apothic_enchanting api -> `apotheosis.ench.api.IEnchantingBlock` (same method names getQuantaBonus/getArcanaBonus).
- Affix: constructor `super(AffixType.X)` (enum STAT/POTION/ABILITY/SOCKET/DURABILITY), no `AffixDefinition`; `getDescription(ItemStack, LootRarity, float)`; `getId()` not `id()`; no `isLevelIndependent`, no `AffixBuilder`, no `StepFunction.fromBounds`.
- AffixInstance is a record: `affix()`/`rarity()` (DynamicHolder, call `.get()`)/`level()`; 7.x AffixHelper has getAffixes(ItemStack) and getAffixes(AbstractArrow) only -> custom `ApothicCompats.streamEntityAffixes(Entity)` for other projectiles.
- `LootCategory` 7.x: class-based (NOT enum), register via PUBLIC 4-arg `LootCategory.register(null, name, predicate, slots)` (3-arg is package-private); NONE validator = alwaysFalse; category NAMES are bare strings.
- Attributes: RegistryObject (not Holder), `.setSyncable(true)` exists on Forge 1.20.1, NO `Attribute.Sentiment`. DeferredRegister; nested classes must be force-initialized at mod construction (Comp.bootstrap forceLoad pattern) else "Cannot register new entries to DeferredRegister after RegisterEvent has been fired".
- Damage: no EntityInvulnerabilityCheckEvent/DamageSourceExtension on 1.20.1 -> pattern = cancel LivingAttackEvent + re-hurt with custom DamageType (`apothic_compats:magic_projectile`, JSON in `data/apothic_compats/damage_type/` + tags is_magic/bypasses_armor under `data/minecraft/tags/damage_type/`). `DamageSources.source(key, direct, causing)` is PRIVATE -> use public ctor `new DamageSource(holder, direct, causing)`; holder via `target.level().registryAccess()` (Entity has no registryAccess in 1.20.1). Guard: `src.is(MAGIC_DAMAGE_TAG)` (own TagKey; vanilla DamageTypeTags.IS_MAGIC does not exist in 1.20.1).
- Config: `ModConfig.Type.COMMON` (no STARTUP on Forge) + `ModLoadingContext.get().registerConfig(...)` (ModContainer.registerConfig doesn't exist on Forge 1.20.1).
- Mod class: **no-arg constructor** + `FMLJavaModLoadingContext.get().getModEventBus()` (the `(IEventBus, ModContainer)` ctor is NeoForge-only -> NoSuchMethodException crash).
- mods.toml (Forge 47): `mandatory=true` (NOT NeoForge `type="required"`); `[[mixins]]` blocks supported; also add `MixinConfigs` jar manifest attribute.
- Curios 5.2.0-beta.3: `ICurioItem.getAttributeModifiers(SlotContext, UUID, ItemStack)` -> `Multimap<Attribute, AttributeModifier>`; SlotContext has NO stack() (ItemStack is 3rd param); canEquipFromUse(SlotContext, ItemStack) OK.
- Artifice 1.20.1 API nearly identical to 1.21.1 (ComposeShotEvent, AmmoEvent$Consume, BulletImpactEvent extends ProjectileImpactEvent -> use `getRayTraceResult()` not getHitResult, ShotComponents, ValueModifier, ShotProfile.peek/modifyValue, RangedGunAttackGoal(T,float,int,int,int,int), SoundRegistry.INFINITY_BULLET). EntityAttributeModificationEvent on MOD bus; AttributeModifier ops ADDITION/MULTIPLY_BASE/MULTIPLY_TOTAL.
- EntityAttributeModificationEvent fires from ForgeHooks.modifyAttributes AFTER RegisterEvent -> lazy class-init crashes (fixed via forceLoad pattern in Comp.bootstrap).
- Lodestone/Malum/Create 6.0.8 class paths identical to 1.21.1 for the classes we use.

## 5. DATA CONVERSION (8.x -> 7.x)
- Scripts: `_ref\convert-part1/2/3.ps1` (dot-sourced together), source snapshot `_ref\gen121` (git archive of 1.21.1 branch). Output: `src/main/resources/data/` (static resources — 7.x has NO datagen providers for this content).
- Folder structure identical: affixes/, affix_loot_entries/, gear_sets/, gems/, recipe -> **recipes** (vanilla rename), tags/. DROPPED (no 7.x equivalent): apothic_invaders, data_maps, extra_gem_bonuses, rarity_override, affixes/gun/spell (ISS enchant affixes), irons_apothic:spell_trigger affixes, apotheosis:enchantment affixes.
- Mappings: rarity keys de-namespaced; gem cut levels cracked/chipped/flawed/normal/flawless/perfect -> common/uncommon/rare/epic/mythic/ancient; StepFunction `{min,max,step}` -> `{min, steps:ceil((max-min)/step), step}` (7.x uses `{min,steps,step}`); operations add_value->ADDITION etc.; attributes `apothic_attributes:*`->`attributeslib:*`, dropped 1.21-only vanilla attrs (burning_time, oxygen_bonus, block_break_speed, entity_interaction_range, submerged_mining_speed), `neoforge:swim_speed`->`forge:swim_speed`; categories de-namespaced + group expansion (melee_weapon->[sword,heavy_weapon] etc.); affix_loot tiers (frontier/haven/ascent/summit/pinnacle) -> min/max rarity + max weight; gem_class string form handled; multi_attribute partial values rarity-filled (Fill-Rarities).
- affix_loot_entries 7.x schema REQUIRES `dimensions` (added `"dimensions":[]` to 107 flat curios entries).
- Salvaging recipes need `"conditions"` key (vanilla RecipeManager ignores `"forge:conditions"`) — cause of a hard crash via unchecked NoSuchElementException in SalvagingRecipe$Serializer.fromJson:97.
- All conditions: `forge:mod_loaded` (was neoforge:mod_loaded — bulk fixed in 849 files).
- Post-conversion data fixes: festive values flattened to bare StepFunction (7.x FestiveAffix VALUES_CODEC); executing/thunderstruck shapes were already fine.
